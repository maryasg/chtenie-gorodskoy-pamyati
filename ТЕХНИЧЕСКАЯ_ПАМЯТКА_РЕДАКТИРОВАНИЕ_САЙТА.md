# Техническая памятка: как править тексты и картинки на сайте

Эта памятка написана для редактирования сайта прямо через GitHub.

Короткий ответ: **да, заголовки, описания, подписи, источники и часть картинок можно править прямо на GitHub**. Главное - менять только текстовые значения внутри кавычек и не трогать названия переменных, импорты, скобки и служебные настройки.

---

## 1. Как редактировать через GitHub

1. Откройте репозиторий на GitHub.
2. Найдите нужный файл по пути из этой памятки.
3. Нажмите на файл.
4. Нажмите значок карандаша **Edit this file**.
5. Исправьте текст.
6. Внизу страницы заполните короткое описание изменения, например:
   - `Исправлен заголовок на странице карты`
   - `Добавлены подписи к фото MOSCOW_004`
7. Нажмите **Commit changes**.
8. Если GitHub предложит сделать Pull Request - создайте его. После проверки изменения можно будет влить в основную ветку.

После попадания изменений в основную ветку `main` сайт публикуется через GitHub Pages. За публикацию отвечает `.github/workflows/deploy-pages.yml`.

---

## 2. Главное правило безопасности

В файлах `.ts` и `.tsx` можно править текст, который стоит **внутри кавычек**:

```ts
title: 'Старый заголовок',
```

можно заменить на:

```ts
title: 'Новый заголовок',
```

Но не меняйте служебные части:

```ts
title:
id:
const
export
import
{ } [ ] ( )
```

Если случайно удалить кавычку, запятую или скобку, сайт может не собраться.

## 3. Где что лежит

### Корень проекта

| Путь | Что это | Можно ли править |
|---|---|---|
| `README.md` | Короткое описание проекта и команды запуска | Можно править текст |
| `ТЕХНИЧЕСКАЯ_ПАМЯТКА_РЕДАКТИРОВАНИЕ_САЙТА.md` | Эта памятка | Можно править текст |
| `package.json`, `package-lock.json` | Технические зависимости сайта | Не трогать без разработчика |
| `vite.config.ts` | Настройки сборки и адреса сайта на GitHub Pages | Не трогать без разработчика |
| `tsconfig*.json`, `eslint.config.js` | Настройки TypeScript и проверки кода | Не трогать |
| `.gitignore` | Что Git не должен загружать | Обычно не трогать |

Если в проекте появится папка `content/`, она будет предназначена для более удобной редакции текстов в YAML/Markdown. Сейчас основной контент сайта лежит не там, а в `src/data/` и `src/pages/`.

### `.github/`

| Путь | Что это | Можно ли править |
|---|---|---|
| `.github/workflows/deploy-pages.yml` | Автоматическая сборка и публикация сайта | Не трогать без разработчика |

Если сайт перестал обновляться после изменения, на GitHub нужно смотреть вкладку **Actions**: там будет видно, прошла ли сборка.

Это папка для файлов, которые сайт открывает напрямую по URL: картинки, SVG, JSON-разметка фасадов.

| `public/explorer/MOSCOW_003/` | Фасады и разметка для здания MOSCOW_003 | Можно заменять только подготовленным экспортом Archiview |
| `public/explorer/MOSCOW_004/` | Фасады и разметка для здания MOSCOW_004 | Можно заменять только подготовленным экспортом Archiview |

### `src/`

Это основная папка сайта.

| Путь | Что это | Можно ли править |
|---|---|---|
| `src/App.tsx` | Маршруты страниц сайта | Не трогать без разработчика |
| `src/main.tsx` | Точка запуска React | Не трогать |

| `src/pages/` | Тексты и структура отдельных страниц | Можно править небольшие тексты в кавычках |
| `src/components/` | Переиспользуемые блоки интерфейса | Лучше не трогать, кроме явных подписей/лейблов |

Это отдельные инструменты Archiview для подготовки фасадов, разметки и копирования результата на сайт.

| `tools/archiview-cv/*.py`, `*.ps1`, `*.bat` | Программа и скрипты обработки | Не трогать без разработчика |

## 4. Где править тексты на сайте

### Шапка и меню

Файл: `src/components/Layout.tsx`

Что там:

- название сайта в шапке;
- подпись `Пилот · 4 здания · Archiview`;
- пункты меню: `Карта`, `Метод`, `Экскурсия`, `Исследователь`.

Можно менять:

```ts
{ to: '/method', label: 'Метод' },
```

Например:

```ts
{ to: '/method', label: 'Методика' },
```

Не меняйте `to: '/method'`, если не хотите менять адрес страницы.

### Главная карта

Файл: `src/pages/MapPage.tsx`

Что там:

- маленькая подпись `Пилот Москва`;
- заголовок `Карта пилота`;
- вводный текст над картой.

Это можно править прямо в тексте между тегами:

```tsx
<h1>Карта пилота</h1>
```

### Страница методологии

Файл: `src/pages/MethodPage.tsx`

Что там:

- главный заголовок страницы метода;
- блок `PIPELINE` - шаги процесса;
- блок `TECH_STACK` - из чего состоит система;
- блок `FILES` - какие файлы лежат в экспорте;
- блок `LIMITS` - ограничения прототипа;
- блок `DEMO_CASES` - что показывать на презентации.

Можно править тексты `title`, `text`, `desc`.

Осторожно: не удаляйте запятые между пунктами массива.

### Страница экскурсии

Файл: `src/pages/TourPage.tsx`

Что там:

- общий заголовок `Готовая экскурсия`;
- вводный текст страницы;
- кнопки `Назад`, `Далее`, `Сначала`, `Открыть карточку`.

Сами точки маршрута лежат отдельно:

Файл: `src/data/tour.ts`

Там можно менять:

- `title` - название точки;
- `methodologyNote` - пояснение к точке;
- порядок точек в массиве `PILOT_TOUR`.

Не меняйте `buildingId`, если не уверены: он связывает точку маршрута с карточкой здания.

### Страница исследователя

Файл: `src/pages/ExplorerPage.tsx`

Что там:

- заголовок `Режим исследователя`;
- предупреждение про демо-режим;
- подсказки съемки в массиве `TIPS`;
- демо-гипотезы в массиве `MOCK_TRACES`;
- тексты кнопок и шагов.

Можно править только формулировки. Логику загрузки файла лучше не трогать.

### AR-preview

Файл: `src/pages/ARPage.tsx`

Что там:

- заголовок AR-страницы;
- пояснение, почему для side-by-side-кейса AR-preview не показывается;
- пояснение для зданий без экспорта Archiview.

Можно править текстовые формулировки. Логику условий лучше не менять.

## 5. Карточки зданий: главное место для контента

Карточки зданий лежат здесь:

```txt
src/data/buildings/
  moscow001.ts
  moscow002.ts
  moscow003.ts
  moscow004.ts
  index.ts
```

Один файл = одно здание.

### Какие поля можно править

Примерные поля в карточке:

| Поле | Что означает | Можно ли править |
|---|---|---|
| `name` | Название здания | Да |
| `alternativeNames` | Альтернативные названия | Да |
| `address` | Адрес | Да |
| `lat`, `lng` | Координаты на карте | Только аккуратно |
| `mapStatus` | Статус на карте | Да, но только из разрешенных значений |
| `style` | Архитектурный стиль | Да |
| `yearBuilt` | Дата/период постройки | Да |
| `headline` | Короткий главный тезис под заголовком | Да |
| `methodologyNote` | Кураторская методическая заметка | Да |
| `architect` | Архитектор | Да |
| `protectionStatus` | Охранный статус | Да |
| `summary` | Главный текст карточки | Да |
| `verification` | Блок достоверности, экспертиз, СМИ | Да, аккуратно |
| `memoryTraces` | Что видно на фасаде | Да |
| `artifacts` | Сохранившиеся элементы | Да |
| `timeline` | Исторические слои | Да |
| `photos` | Визуальные материалы и ссылки | Да |
| `sources` | Источники | Да |
| `hotspots` | Координаты зон подсветки | Лучше не трогать без проверки |

### Что не менять в карточке без необходимости

| Поле | Почему |
|---|---|
| `id` | Это внутренний адрес карточки. Если поменять, старые ссылки сломаются |
| `cardId` | Связывает карточку с папкой в `public/explorer/MOSCOW_XXX/` |
| `traceId`, `artifactId` | Связывают подсветку с конкретным следом или элементом |
| `hotspots.x`, `hotspots.y`, `width`, `height` | Это координаты подсветки на изображении |

### Разрешенные статусы достоверности

В `confidence` можно использовать только эти значения:

```ts
'confirmed'
'probable'
'needs_verification'
'typological_hypothesis'
```

На сайте они показываются так:

| Значение | На сайте |
|---|---|
| `confirmed` | Подтверждено |
| `probable` | Вероятно |
| `needs_verification` | Требует проверки |
| `typological_hypothesis` | Типологическая гипотеза |

### Разрешенные статусы карты

В `mapStatus` можно использовать только:

```ts
'verified'
'preliminary_reading'
'in_preparation'
'no_data'
```

Подписи этих статусов лежат в `src/data/statuses.ts`.

## 6. Как добавить новый текстовый пункт в карточку

Например, нужно добавить новый след памяти в `memoryTraces`.

Было:

```ts
memoryTraces: [
  {
    id: 'T001',
    type: 'preserved_signage',
    title: 'Вывеска Фалькевича',
    period: 'около 1918-1919',
    confidence: 'confirmed',
    userMessage: 'Одна из сохраненных вывесок Москвы.',
  },
],
```

Добавляем второй пункт:

```ts
memoryTraces: [
  {
    id: 'T001',
    type: 'preserved_signage',
    title: 'Вывеска Фалькевича',
    period: 'около 1918-1919',
    confidence: 'confirmed',
    userMessage: 'Одна из сохраненных вывесок Москвы.',
  },
  {
    id: 'T002',
    type: 'ghost_sign_layer',
    title: 'Нижний слой вывески',
    period: 'начало 1920-х',
    confidence: 'probable',
    userMessage: 'Под верхней вывеской читается более ранний слой.',
  },
],
```

Важно:

- у каждого пункта должен быть свой `id`;
- между пунктами нужна запятая;
- текст должен быть в кавычках;
- если в тексте есть апостроф `'`, лучше заменить кавычки строки на обратные:

```ts
title: `Текст с апострофом`,
```

## 7. Как добавлять новые картинки

### Вариант А: картинка внутри следа памяти

Это самый простой вариант: добавить фото к конкретному пункту в блоке `memoryTraces`.

1. Положите картинку в папку:

```txt
public/details/MOSCOW_XXX/
```

Например:

```txt
public/details/MOSCOW_004/sign-new-2026.jpg
```

2. В карточке здания добавьте к нужному следу:

```ts
imagePath: 'details/MOSCOW_004/sign-new-2026.jpg',
imageCaption: 'Подпись к фотографии',
```

Пример:

```ts
{
  id: 'T005',
  type: 'detail_photo',
  title: 'Новая деталь фасада',
  period: '2026',
  confidence: 'confirmed',
  userMessage: 'Описание того, что видно на фото.',
  imagePath: 'details/MOSCOW_004/sign-new-2026.jpg',
  imageCaption: 'Деталь фасада, полевая съемка 2026',
},
```

Важно: путь начинается с `details/...`, без `public/` в начале.

### Вариант Б: заменить главное изображение фасада/разметки

Главные изображения для Archiview лежат в:

```txt
public/explorer/MOSCOW_001/
public/explorer/MOSCOW_003/
public/explorer/MOSCOW_004/
```

Типовые имена:

```txt
historical-rectified.png
modern-rectified.png
marked-facade.png
marked-facade-labeled.png
side-by-side-marked.png
annotations.json
facade-project.json
```

Эти файлы лучше заменять не вручную, а экспортом из Archiview, потому что PNG и JSON должны совпадать по координатам. Если заменить только картинку, подсветка может съехать.

Связь сайта с этими файлами прописана в:

```txt
src/data/explorer/archiviewAssets.ts
```

Там указано, какие картинки показывать для каждого здания.

### Как загрузить картинку через GitHub

1. Откройте нужную папку, например `public/details/MOSCOW_004/`.
2. Нажмите **Add file** -> **Upload files**.
3. Перетащите картинку.
4. Внизу нажмите **Commit changes**.
5. Потом добавьте путь к картинке в карточку здания.

Рекомендации по именам файлов:

- использовать латиницу;
- без пробелов;
- маленькие буквы;
- вместо пробелов ставить дефис;
- хорошо: `sign-gas-2026.jpg`;
- плохо: `Новая фотка 1.JPG`.

## 8. Как добавить новое здание

Это уже более рискованная правка. Лучше делать через Pull Request и проверку.

Минимальные шаги:

1. Создать новый файл:

```txt
src/data/buildings/moscow005.ts
```

2. Скопировать структуру из существующего файла, например `moscow004.ts`.
3. Изменить:

```ts
export const MOSCOW_005: Building = {
  id: 'MOSCOW_005_short_name',
  cardId: 'MOSCOW_005',
  ...
}
```

4. Зарегистрировать здание в:

```txt
src/data/buildings/index.ts
```

Нужно добавить импорт:

```ts
import { MOSCOW_005 } from './moscow005'
```

и добавить в массив:

```ts
export const BUILDINGS: Building[] = [MOSCOW_001, MOSCOW_002, MOSCOW_003, MOSCOW_004, MOSCOW_005]
```

5. Если есть экспорт Archiview, добавить папку:

```txt
public/explorer/MOSCOW_005/
```

6. И добавить запись в:

```txt
src/data/explorer/archiviewAssets.ts
```

7. Если здание должно быть в экскурсии, добавить его в:

```txt
src/data/tour.ts
```

## 9. Что можно править самой

Безопасно:

- заголовки страниц;
- описания зданий;
- подписи к фотографиям;
- список источников;
- тексты маршрута экскурсии;
- формулировки методологии;
- статусы `confirmed`, `probable`, `needs_verification`;
- добавлять фото в `public/details/...` и подключать через `imagePath`;
- добавлять ссылки на PastVu, mos.ru, статьи СМИ.

Аккуратно:

- координаты `lat`, `lng`;
- порядок зданий в `BUILDINGS`;
- порядок экскурсии в `PILOT_TOUR`;
- блоки `verification`, если добавляется много ссылок;
- названия файлов в `public/explorer/...`.

Лучше не трогать без разработчика:

- `package.json`;
- `package-lock.json`;
- `vite.config.ts`;
- `.github/workflows/deploy-pages.yml`;
- `src/App.tsx`;
- `src/main.tsx`;
- `src/types/`;
- `src/lib/`;
- геометрию, overlay, side-by-side и координаты `hotspots`;
- Python/PowerShell/BAT-скрипты в `tools/archiview-cv/`.

## 10. Частые поломки и как их узнать

### Сайт не собрался после правки

Обычно причина:

- удалена кавычка;
- пропущена запятая;
- лишняя скобка;
- изменено служебное имя поля;
- путь к картинке написан неправильно.

Где смотреть ошибку:

1. Откройте GitHub.
2. Перейдите во вкладку **Actions**.
3. Откройте последнюю сборку.
4. Если там красная ошибка, значит сайт не опубликован.

### Картинка не показывается

Проверьте:

- файл точно загружен в `public/...`;
- в `imagePath` нет `public/` в начале;
- совпадает регистр букв: `MOSCOW_004` и `moscow_004` - разные пути;
- расширение совпадает: `.jpg`, `.jpeg`, `.png`, `.webp`;
- в имени файла нет пробелов и русских букв.

### Подсветка фасада съехала

Скорее всего, заменили PNG без соответствующего `annotations.json` или `facade-project.json`. Для фасадных экспортов лучше использовать Archiview и копировать весь комплект файлов вместе.

## 11. Самый безопасный рабочий процесс

1. Для простого текста правьте только один файл за раз.
2. После правки создавайте Pull Request, если GitHub предлагает.
3. Дождитесь зеленой проверки сборки.
4. Просмотрите страницу сайта после публикации.
5. Для картинок сначала загрузите файл в `public/details/...`, потом отдельным изменением подключите его в карточке здания.
6. Для фасадов Archiview заменяйте весь комплект файлов, а не одну картинку.

Если сомневаетесь, лучше менять только текст внутри кавычек и не трогать скобки, запятые, импорты и служебные идентификаторы.
